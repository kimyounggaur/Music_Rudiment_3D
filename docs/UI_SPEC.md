# 화면 구현·검수

가로 휴대전화는 질문/실험/악보와 재생·다음 흐름, 세로는 문서 흐름으로 재배치한다. 닫을 수 있는 가로 권장 안내를 제공하며 방향 잠금·강제 fullscreen·zoom 차단 없음. 작은 높이에서는 정상 스크롤로 핵심 조작에 접근한다.

2D 시간 블록과 실제 Three.js WebGL2 입체 블록은 동일 eventId/명령을 사용한다. 입체 블록의 X 시작점·너비는 시간에 비례하고 높이·깊이는 고정이다. 음표는 채운 상자, 쉼표는 같은 시간 길이의 빈 점선 윤곽이다. 실제 Canvas 탭은 Raycaster로 선택하고 8px 이상 움직인 드래그는 선택하지 않는다. 작은 음가도 별도 44px DOM 순서 버튼과 키보드로 선택할 수 있다. 질문·기호·악보는 일반 화면에 표시한다.

입체 화면의 기본·낮은 각도는 사용자가 누르는 고정 시점이며 자동 회전은 없다. DPR 최대1.5와 변경 시 그리기를 사용한다. 모션 감소는 이동 재생선을 숨기며 순서 목록·현재 이벤트 강조는 남긴다. 초기화 실패·문맥 손실·지연 모듈 실패 때는 재생을 정지하고 같은 편집 리듬·학습 진행을 2D로 표시한다. 저사양 2D 전환 버튼도 제공한다. CSS3D 대체 화면은 초기 빌드의 이력이다.

실제 VexFlow SVG는 시간 블록의 선형 좌표를 기보 간격으로 쓰지 않는다. 박별 빔, C4 덧줄, 온쉼표 네 번째 선·반쉼표 가운데 선, 선택·재생 강조, 좁은 화면 악보 전용 가로 스크롤을 검사했다. 글꼴이 실패하면 텍스트 목록과 44px 재시도 버튼으로 복구하며 lesson data를 유지한다.

초기 file-origin Chromium에서844×390,667×375,568×320,390×844,360×640,320×640,1024×768,1366×768의6장면을 캡처하고 body overflow·44px transport·모드/화면 전환 보존을 검사했다. 전체6장면을 포인터·소리 없이 키보드48행동으로 완료·저장·복구한 이력도 있다. 이후 실제 production HTTP Three 검사에서는 WebGL2 Canvas, DPR1.5, 탭/드래그·키보드 선택, 가로/세로 전환 보존, 실제 context loss·WebGL 부재·모듈 실패의 2D 전환까지 9개가 통과했다. 실행별 artifact와 검사 범위는 [검증 표](qa/TEST_MATRIX.md), [Three 검수 기록](qa/Three_REVIEW.md)을 따른다.

최종 Three 검사 대상 index SHA-256은 `6d4ca09b0288cdd5bdf376fbdc7168e13e432bdb919f6b6151d7f348ad08383d`다. 가림 없는 Canvas 캡처에서 음표 두 개와 같은 길이의 빈 점선 쉼표 두 개를 직접 검토했다. 긴 페이지 전체 캡처에는 sticky 재생 막대가 당시 화면 위치에 찍힐 수 있어 해당 Canvas 캡처로 입체 윤곽을 별도 검토했다. 실제 SR·터치 기기·notch·주소창·softkeyboard·iOS Safari·청취·교육자 승인은 미검증이다.

## v2.1 추가 고정 계약 — 화면에는 언제나 책만

2026-10-27 추가 사용자 요구를 반영한다. 이 개정은 문서 변경이며 앱 구현·배포 완료가 아니다. v2.0 원본은 변경하지 않는다.

- **BOOK-ONLY:** 최초 진입뿐 아니라 표지 안착, 열기, 학습, 페이지 넘김, 안착, 이전 쪽 복귀, 닫기까지 정상 앱 화면에는 책과 그 책에 속한 내용만 보인다. 책 바깥 navigation, sidebar, HUD, floating toolbar, 고정/상시 재생바, 대시보드, 토스트를 만들지 않는다. 외부 UI 점유 15% 같은 예외도 없다.
- “책만”은 악보·교육 문장·문항·3D 장면을 없애라는 뜻이 아니다. 모두 종이 면·플랩·책 안 조작에 귀속한다. 배경은 무늬 없는 중립색과 책의 접촉 그림자만 허용하며 책상 소품·장식 모델은 없다.
- **COVER-INTRO:** 접속 시 닫힌 책을 이미 화면 안에 보여 주고, 카메라가 짧게 이동해 표지 중앙을 실제 앱 viewport 중앙에 안착시킨다. 책이 바깥에서 날아들거나 자동으로 펼쳐지는 연출이 아니다. 이후 사용자가 표지를 터치/키보드로 열고 페이지 모서리를 직접 드래그한다.
- **EDGE-NAV:** 열린 책의 왼쪽 바깥 끝에는 이전, 오른쪽 바깥 끝에는 다음 **책에 부착된 책갈피 모양 버튼**을 둔다. 터치·클릭과 ArrowLeft/ArrowRight는 동일 페이지 넘김 명령을 실행한다. 직접 모서리 드래그도 그대로 필수다.
- 모든 보조 기능은 책 안 목차 페이지·플랩·책 안 설정 페이지로 연다. 시각 외부 패널을 접근성 핑계로 추가하지 않는다. DOM 시맨틱, 스크린리더 대체 텍스트, 키보드 조작, 페이지 위 focus 표시는 유지한다. 브라우저 주소창·OS 키보드·브라우저 권한창은 앱이 숨길 수 있는 UI가 아니며 강제 전체화면/권한 우회로 숨기지 않는다.

### 제공된 실제 표지 자산 확인

[사용자 제공 표지](https://drive.google.com/file/d/1IJhuTm6mP05iyDQFikpdVMUhRg5FI2v2/view)는 `음악이론 교과서_표지(크몽) 01.ai`, 11,076,323 bytes, 수정시각 `2026-10-27T03:58:22.147Z`, 부모 `14m-1MK1CgMovBx0ssWSm35CZQRmQ6Fns`다. Drive MIME은 application/postscript이나 실제 원본 바이트는 PDF 1.5 호환 Illustrator 파일이며 A4 세로 595.276×841.89pt, 1페이지다. 실제 렌더에서 ‘한국생활음악강사협회 / 아주 쉽게 배우는 음악이론 교과서’와 청색 계열 악보·책·악기 삽화를 확인했다. 이 파일은 설계서가 아니라 표지 원화다. 이것만으로 3D 모델·페이지 애니메이션이 제공됐다고 하지 않는다.

원본 AI는 보존한다. 구현에서는 승인된 변환 사본을 앞표지 texture로 사용하고 제목·로고·삽화·테두리를 자르거나 재작성하지 않는다. A4 세로 종횡비를 유지하고 **앞표지 front-face 자체**의 폭:높이를 595.276:841.89로 맞춘다. 종이와 앞표지에 같은 치수를 준 뒤 임의 여백을 더하는 방식은 금지한다. 앞표지 치수에서 종이 여백을 빼 페이지 치수를 파생한다. 가로 웹앱이라는 이유로 표지를 가로로 늘리지 않는다. 기존 W=3,H=3.4 제안보다 이 표지 비율을 우선한다. 뒤표지/책등의 별도 원화는 확인하지 못했으므로 앞표지를 복제하거나 임의 문구를 지어 넣지 않는다. 원화가 없는 면은 중립 단색으로 설계하고 미제공 상태를 기록한다. PDF 미리보기는 편집가능 AI 레이어·폰트·권리 전체를 검증한 증거가 아니다.

### 진입 카메라와 중앙 정합 계약

1. `bootLoading → introReady → introMoving → coverIdle → opening → spreadIdle`로 구분한다. 기존 `closed`는 `coverIdle`의 책 상태 명칭으로 호환한다. 카메라는 별도 `loading/intro/settled/reframing/suspended` 상태다. `coverIdle + camera.settled + firstSpreadReady`에서만 OPEN을 한 번 수락한다. 표지 렌더 이전 검은 빈 화면 대신 Three 지연 import나 11MB 원본 AI 로딩에 선행하는 정적 HTML/CSS 닫힌 책 silhouette 또는 허가된 소형 preview를 첫 paint에 그리며 로딩 상태는 표지 안에만 둔다.
2. 정면에 가까운 읽기 가능한 표지 구도로 약 900–1400ms의 단조 ease-in-out 카메라 위치·target 보간을 초기 제안한다. 이 시간은 원본 실측이 아니다. 일반 모션에서는 시작 pose와 endpoint 사이에 가시적인 카메라 위치·각도 또는 투영 크기 차이를 두고 0/50/100% 연속 영상으로 실제 이동을 증명한다. 동일 pose를 시간만 기다리는 구현은 실패다. reduced-motion/skip은 의도적 예외다. 책 자체를 자동 회전하지 않고 표지 제목을 끝까지 읽을 수 있게 한다. 도입 카메라 연출은 첫 진입 전용이며 OPEN/CLOSE 재구도는 6-A를 따른다. 페이지 드래그/넘김 도중 카메라를 돌리지 않는다.
3. **중앙의 정의:** CSS pixel 단위 앱 visual viewport의 크기를 Wv,Hv라 하면 목표 T=(Wv/2,Hv/2)다. 캔버스 client rect와 visualViewport offset을 같은 좌표계로 변환한다. 표지 front-face UV (0.5,0.5)를 월드행렬→view→projection으로 투영한 C를 사용한다. 책등 원점·BookRoot 원점·전체 펼침면 중심으로 대체하지 않는다. 원근 사각형 꼭짓점 평균도 표지 UV중심 투영과 같다고 가정하지 않는다. 중앙 오차 ||C−T||≤2 CSS px를 안착 수용 기준으로 한다.
4. safe-area inset과 추가 12px 여백으로 안전 사각형을 만든다. **safe-area 중앙으로 목표를 슬쩍 이동하지 않는다.** 실제 화면 중앙 T를 유지한 상태에서 책 전체가 안전 사각형에 들어가도록 카메라 거리를 증가시키거나 FOV를 확대하거나 모델의 균일 scale을 감소시키고 near/far를 재계산한다. 비대칭 노치에서도 이 기준을 유지한다. 표지 네 꼭짓점뿐 아니라 두께·책등·뒷표지·종이묶음·책갈피 bounds를 검사한다. NDC와 near/far clipping도 검사한다. 배경 그림자는 필수 본체 bounds에 포함하지 않아도 된다.
5. 844×390, 667×375, 568×320, 390×844, 360×640 및 비대칭 safe-area에서 intro 전 구간과 최종 상태를 검증한다. portrait에서 cover를 가로로 변형하거나 CSS 90도 회전시키지 않는다. 가로 우선이지만 세로 접근을 막지 않는다. 확대/가독성에 따라 열린 교재는 페이지 안 읽기/스크롤 경로를 제공한다.
6. resize·orientation·주소창 변화는 ResizeObserver와 visual viewport 변화로 재측정한다. 현재 pose에서 새 endpoint로 재보간하며 intro를 처음부터 재시작하지 않는다. 터치 드래그 중 회전은 기존 TURN_CANCEL 정책으로 안정 페이지를 복원한 후 재구도한다. intro 완료 후 열린 책에는 펼침면과 턴 최고점 전체 bounds를 사용한다. 단순히 닫힌 앞표지 중심을 모든 열린 상태에도 강제하지 않는다.
6-A. **표지↔학습 카메라 연결:** 최초 버전은 coverIdle과 spreadIdle의 카메라 방향/quaternion을 동일하게 선택한다(학습 사선 후보 중 표지 글자도 읽히는 각도). intro 출발 pose만 다를 수 있다. OPEN 수락 후 `opening + camera.reframing`에서 커버 힌지와 함께 카메라 위치·거리·target을 제어된 단일 전이로 보간해 펼침면 중심/bounds에 맞춘다. quaternion 회전은 하지 않는다. 사용자가 페이지를 드래그할 때 자동 재구도하는 것과 구분한다. 커버와 카메라가 모두 settled된 뒤만 sceneEnter/학습 입력을 활성화한다. CLOSE는 sceneExit→cover closing+동일 방향 reframe→앞표지 UV중앙 재정합 순서이며 두 완료 후 coverIdle로 commit한다. 완전히 다른 학습 각도가 필요하면 별도 설계 변경으로 다루고 순간 카메라 점프를 허용하지 않는다.
6-B. **확대는 재구도와 별개다:** visualViewport.scale이 사용자 pinch/브라우저 확대를 나타내면 자동 fit·재중앙화를 중지하여 200% 확대를 카메라 축소로 상쇄하지 않는다. 확대 이전 stage layout을 유지하고 브라우저 pan/scroll 및 책 안 읽기 대체를 허용한다. 확대 해제 뒤 안정 viewport에서만 fit을 다시 한다. orientation·주소창만 바뀐 경우와 scale 변화를 구분해 로그한다. visualViewport.scale 하나로 데스크톱 브라우저 page zoom까지 모두 탐지할 수 있다고 가정하지 않는다. 확대 정책은 DPR·layout viewport 변화도 참고하되 불확실한 경우 재축소보다 사용자 확대 보존을 우선하고 실제 브라우저 200% 검수로 확인한다. 텍스트 입력 소프트키보드가 나타나면 focus와 커서를 유지하며 책 전체를 무조건 축소하지 않는다. 필요한 최소 scroll/읽기 영역 이동으로 입력을 드러내고 키보드가 닫힌 뒤 안정 재구도한다. 접근성 확대 상태에서는 전체 책 동시 가시성보다 확대·읽기 가능성이 우선이며 CI02의 무crop과 CI01 중앙 정합은 사용자 pinch/pan·키보드 focus 작업이 없는 자동 연출/비확대 기본 구도에서 평가한다. 사용자 조작을 취소해 억지로 중앙 오차를 맞추지 않는다.
7. 표지 안 작은 ‘바로 보기’ 영역과 Escape로 intro를 건너뛰면 동일 endpoint로 즉시 안착한다. 이는 책을 자동으로 여는 명령이 아니다. 임의 표지 탭은 intro 중 skip으로만 소비하고 같은 pointerup이 OPEN으로 중복 전달되지 않게 한다. 다음 명시 입력에서 연다. reduced-motion은 처음부터 endpoint로 렌더하며 자동 pan/zoom은 없다. Tab focus·스크린리더 이름은 표지 안 위치와 연결한다.
8. visibility hide에서는 intro clock을 중지하고 복귀 시 endpoint에 안착시킨다. 로딩 실패는 책 안 재시도/정적 2D 표지 경로로 보이고 오류를 완료로 처리하지 않는다. PDF/AI가 브라우저에서 직접 texture가 된다고 가정하지 않는다. 변환 산출물 불가 시 원화 미적용 상태로 남기며 다른 표지를 원본이라고 표시하지 않는다. WebGL 실패는 동일 표지 비율의 2D 책을 제공한다. 정상 상태에서 외부 오류 패널을 계속 남기지 않는다.

### 책갈피 이전/다음과 입력 충돌 계약

- ‘페이지 넘김’ 명령 한 번은 왼쪽·오른쪽 한 쌍인 **인접 Spread 이동**이다. 물리 PaperLeaf가 넘어가고 앞뒤 인쇄면이 바뀌며, 양쪽 버튼이 각각 별도의 반쪽 페이지를 교체하는 방식이 아니다.
- 좌우 책갈피는 책 가장자리에 붙고 책 변형·투영을 따라 움직인다. 화면 가장자리에 fixed로 고정하지 않는다. 시각형은 작게 하되 최소 44×44 CSS px 목표영역을 확보하고 safe-area 안에 둔다. 다른 페이지/장면에 가려진 버튼은 hit-test와 tabindex에서도 비활성화한다. 눌림·focus 표현도 책 안/책에 부착된 범위에 머문다.
- accessible name은 ‘이전 펼침면’, ‘다음 펼침면’, 첫 펼침면의 이전은 ‘표지로’다. 첫 펼침면에서 이전은 CLOSE_BOOK, 마지막 펼침면의 다음은 aria-disabled이며 빈 페이지로 가지 않는다. 닫힌 표지에서 책갈피는 숨긴다. 표지 열기는 표지 자체 버튼/Enter/Space로 한다.
- button pointerdown은 책갈피가 제스처 소유권을 가져 모서리 curl을 시작하지 않는다. 인접 drag hit zone과 겹치면 버튼 우선이고 단일 입력에 한 번의 명령만 발생한다. 페이지 본문/악기 조작은 기존 gesture owner 분기를 지킨다. 책갈피와 별개의 모서리 grab 영역을 예약해 버튼 hit-zone이 모든 드래그 시작 영역을 덮지 않도록 한다. 44px 목표를 확보할 수 없는 작은 화면에서는 책 안 조작 배치를 재조정하며 직접 드래그를 삭제하지 않는다.
- ArrowLeft/Right는 책 읽기 컨텍스트에서만 PREV/NEXT로 처리한다. 목차/설정 플랩 등 modal owner가 활성화되고 배경이 inert이면, focus가 단순 닫기 버튼이더라도 전역 페이지 hotkey를 중지한다. 해당 플랩의 명시적 탐색 명령만 허용하고 닫은 뒤 책 컨텍스트를 복원한다. input/textarea/select/contenteditable, slider, listbox, combobox, 악기 키보드 등 자체 방향키가 필요한 조작에 focus가 있으면 가로채지 않는다. Ctrl/Alt/Meta 조합, IME 조합 중, 이미 defaultPrevented인 이벤트도 무시한다. 브라우저 뒤로가기 단축키를 바꾸지 않는다. 소비한 이벤트만 preventDefault한다. key repeat는 무시해 길게 누름이 연속 넘김으로 쌓이지 않게 한다.
- 전환 중 실제 새 터치/keydown은 기존 최대1개 pendingIntent 정책에 통합한다. 방향 반전도 현재 전이를 완료한 뒤 마지막 유효1개만 평가한다. 버튼 disabled 스타일을 적용할 경우 이벤트도 차단하며 큐를 받는 상태와 혼용하지 않는다. 표지/마지막 경계 guard를 commit 후 다시 평가한다. 모션 줄이기·2D에도 동일 의미를 유지한다.

## 1 결정과 이번 문서의 범위

**기존 설계서와 프롬프트는 보관하고, 책 경험을 제품의 중심으로 다시 정의한 v2를 별도 문서로 사용한다.** 기존 앱의 음악 계산·기보·오디오·검증 코드는 재사용 후보지만, 탭과 패널 중심의 화면 및 탐색 구조는 다시 만든다. 현재 앱에 책 배경이나 페이지 넘김 효과만 덧붙이는 수정으로는 요구를 충족하지 못한다.

사용자가 요구한 경험은 **닫힌 실제 책의 커버를 펼치고, 종이 페이지를 넘기면, 그 페이지에 속한 내용이 입체적으로 등장하여 움직이는 가로형 모바일 웹 교재**다. 특히 페이지 모서리를 손가락이나 마우스로 잡고 끌어, 손의 진행에 맞춰 종이가 휘고 넘어가는 직접 조작이 필수다. 실제 손 모형을 화면에 표시하는 것은 요구되지 않았다. 책이 장식 배경이고 내용은 별도 대시보드에 나타나는 제품이 아니다. Every Joule의 상호작용 방식과 애니메이션 스타일을 중요한 참고 대상으로 삼되, 원본과 100% 같다고 미리 약속하지 않는다.

첫 구현 게이트는 전체 여섯 장면이 아니다. **표지와 실제 음악 콘텐츠가 있는 두 펼침면**을 먼저 만든다. 표지를 열고, 첫 장면이 종이에서 올라오고, 소리와 악보를 확인하고, 다음 페이지를 넘긴 뒤 되돌아오는 연속 경험을 검증한다. 이 게이트가 실패하면 나머지 장면·교사 기능·배포로 확장하지 않는다.

현재 산출물은 두 Markdown 문서다. 이 문서 작성은 앱 수정, 패키지 설치, 저장소 push, 배포, 사용자 기기 설정 변경, 실제 음악 교육자 승인 또는 실기기 검증을 뜻하지 않는다. 아래 치수·시간·성능값은 별도 표시가 없으면 **v2 초기 제안값**이다. 새로 확인한 공개 코드의 상수·구조는 **정적 코드 확인값**으로 따로 표시하며, 실제 기기에서 잰 체감 시간과 구분한다.

### 2.3 관찰하지 못한 것은 관찰한 것으로 쓰지 않는다

클라우드 브라우저에서는 원본과 제작 앱 모두 WebGL context 생성에 실패했다. 원본의 실제 표지 개폐·페이지 곡률·손가락 추적·플랩·모션 시간·역방향 동작은 직접 확인하지 못했다. 이는 검사 환경의 제약이며 앱 자체의 WebGL 고장 판정이 아니다. 연결된 사용자 PC에서 검증할 권한도 이번 확인 시점에는 확보되지 않았다.

사용자의 “실제 커버를 펼치고 페이지를 넘기면 내용이 3D 애니메이션으로 진행된다”는 설명과 손가락으로 모서리를 직접 잡아 넘기려는 추가 요청을 명시 요구사항으로 채택한다. 공개 번들에서 책·페이지·팝업 lifecycle은 정적으로 확인했으므로 이제 그 구조까지 모두 추정이라고 말할 필요는 없다. 다만 pointer handler 존재만으로 손을 따라 페이지가 연속 변형되는 직접 드래그까지 확인한 것은 아니다. 다만 그 설명에서 원본의 정확한 구현 기술·프레임 수·easing 곡선까지 추정하지 않는다. 후속 승인된 환경 또는 사용자가 제공한 화면 녹화로 확인할 수 있다.

## 3 원본 스타일을 적용하는 방법과 한계

### 3.1 독립 재현의 범위

채택할 목표는 책이 중심인 구도, 단단한 표지와 유연한 종이의 다른 움직임, 페이지의 회전에 연결된 장면 등장·퇴장, 페이지 위 입체 잉크 도식, 절제된 강조색, 직접 조작 후 결과를 확인하는 흐름이다. 음악 콘텐츠·문장·도식·텍스처·코드는 독자 제작하거나 사용권이 확인된 자료를 사용한다.

원본 코드·3D 모델·텍스처·음원·폰트·브랜드가 공개 페이지에서 보인다는 사실만으로 복사 권한이 생기지 않는다. 라이선스 확인 전 원본 자산을 내려받아 제품에 넣거나 번들에서 추출하지 않는다. 원본과 비슷한 동작을 우리 코드로 구현하는 것과 원본 산출물을 그대로 가져오는 것은 다른 일이다. 이 문서는 법률 판단이 아니라 구현 범위와 권리 확인 절차를 정한다.

“스타일을 그대로 적용”의 근거는 **동일 입력 시퀀스의 원본 관측 기록과 실제 시제품의 나란히 비교**다. 구조 재현과 실제 체감 유사도를 나눈다. 사용자가 단계마다 질문 없이 자체 판단해 진행하기를 원하므로 선택적 디자인 승인을 반복 요구하지 않는다. 객관적 책 동작 게이트가 통과하면 이미 허용된 개발 범위 안에서 진행하되, 관측하지 못한 원본 체감과 사용자의 주관적 최종 수용은 미확인으로 남긴다.

### 3.3 추가 공개 코드 조사에서 확인한 것

2026년 10월 27일 공개 앱 HTML이 가리키는 [main-CpVTDnX_.js](https://iamtechartist.com/Apps/every-joule/assets/main-CpVTDnX_.js)를 읽은 조사에서는 다음 구조가 확인됐다. 이 자료는 배포 번들의 정적 분석이지 원본 개발 소스·설계 파일을 확보한 것은 아니다.

| 코드에서 확인한 항목 | 확인 수준 | v2에 적용할 판단 |
|---|---|---|
| 책 생성, 표지와 일반 페이지의 다른 분기, 종이·인쇄 shader | 공개 코드 정적 확인 | 책을 별도 엔진으로 만들 근거가 충분함 |
| 하위 페이지 이동 기본 약 1.1초, 상위 전환 기본 약 1.15초 | 코드 기본값, 실제 체감 미측정 | 초기 page turn 비교 기준으로 사용하되 덮어쓰기·조건 분기를 확인 |
| cubic·quadratic 계열 ease-in-out, 다중 잎 지연 상한 약 0.085초 | 코드 함수·조건 확인 | 표지·낱장·여러 장의 분기와 시간 배율을 구분 |
| 넘김 전 퇴장, 도착 후 장면 활성화, 연속 입력 queue | 코드 흐름 확인 | page/scene coordinator를 명시적으로 구현 |
| 포인터 구분·모션 줄이기·로컬 진행 처리 | 코드 존재 확인 | 실기 동작과 직접 드래그 품질은 별도 검증 |

[sound-vOpPkm07.js](https://iamtechartist.com/Apps/every-joule/assets/sound-vOpPkm07.js)에는 책·페이지·플랩 효과음 호출과 파일 참조가 있다. 실제 소리를 듣거나 라이선스를 확인한 것은 아니다. v2 음악 학습에서는 효과음을 기본 끄고, 필요하면 허가된 독자 음원으로 선택 제공한다.

원본의 연속 입력은 최신 목적지를 보관하고 현재 목적지를 다시 요청하면 대기를 취소하는 코드다. v2 초기 시제품의 한 단계 pendingIntent 정책은 안전한 독자 선택이며 원본과 완전히 같은 탐색 정책이라고 주장하지 않는다. 다중 쪽 이동을 추가할 때 해당 차이를 비교표에 남긴다.

조회한 번들들에서는 sourceMappingURL을 찾지 못했다. 이것은 사이트 전체에 원본 소스나 다른 map이 없다는 증명이 아니다. 코드·자산 복제 허가도 확인되지 않았다. **현재 근거로는 책·페이지·장면 연동의 정밀한 독립 재현 가능성이 높지만, 100% 같은 실기 체감은 아직 증명되지 않았다.** 직접 잡고 끄는 UX는 사용자 추가 요구로 별도 필수화한다.

## 4 제품 경험의 고정 계약

1. 지원되는 WebGL 환경의 새 방문은 닫힌 3D 책 표지에서 시작한다. 설명 패널 여섯 개를 먼저 보여주지 않는다.
2. 표지를 열면 책등과 힌지에 연결된 커버가 움직이고 실제 펼침면이 드러난다.
3. 다음·이전 이동은 물리적 페이지 전이를 통한다. 모서리를 직접 잡고 끌기, 중간에서 멈추기, 되돌리기, 손을 놓아 완료 또는 복귀하기가 필수이며 클릭 넘김만으로 통과하지 않는다. 내용 교체에 단순 fade만 붙인 것은 기본 3D 모드의 페이지 넘김으로 인정하지 않는다.
4. 펼침면이 안착한 뒤 그 페이지에 소속된 3D 장면이 올라온다. 콘텐츠가 별도 공중 박스처럼 떠 있으면 실패다.
5. 페이지를 떠나면 해당 장면의 입력·시간축·소리가 멈추고, 물체가 종이로 접히거나 내려간 뒤 페이지가 넘어간다.
6. 이전 페이지로 돌아오면 학습자가 만든 데이터와 답은 보존된다. 소리는 자동으로 재개되지 않는다.
7. 정확한 악보와 읽어야 할 문장은 2D로 유지하되, 페이지에 속한 인쇄물로 보이고 별도 카드 대시보드로 분리되지 않는다.
8. 상단 여섯 탭·상시 좌측 설명 패널·하단 고정 재생바를 주 화면으로 되살리지 않는다. 목차·교사·접근성 도구는 요청 시 책 안 페이지 또는 플랩으로만 열린다.
9. 가로 우선이지 가로 강제는 아니다. 세로·2D·무음·모션 줄이기에서도 같은 학습 목표와 저장 데이터를 사용한다.
10. 책 체험의 시각·동작 게이트와 음악 정확성 게이트는 둘 다 필수다. 어느 하나의 통과가 다른 하나의 실패를 상쇄하지 않는다.

## 5 책 구조와 콘텐츠 배치

### 5.1 식별자와 페이지의 의미

Book은 표지, 뒷표지, 책등, 종이 묶음, 순서가 있는 Spread 목록을 가진다. Spread는 동시에 보는 왼쪽과 오른쪽 두 페이지다. Scene은 한 펼침면에 속한 학습 장면이며, 실제 PaperLeaf는 앞면과 뒷면을 가진 물리 메시다. 세 가지 ID를 같은 숫자로 혼용하지 않는다.

첫 단원은 표지와 6개 학습 펼침면으로 구성한다. 별도 목차 화면을 통과해야 수업이 시작되는 구조는 피하고, 첫 펼침면에서 바로 음악을 만난다. 목차는 책 안 별도 인쇄 버튼으로 여는 보조 페이지다. 좌우 가장자리 책갈피는 이전/다음 이동 전용이다.

| 순서 | 펼침면 ID | 학습 내용 | 왼쪽 페이지 | 오른쪽 페이지 |
|---|---|---|---|---|
| 표지 | cover | 첫 진입 | 닫힌 상태에서는 보이지 않음 | 제목과 책 열기 유도 |
| 1 | spread-duration-01 | 긴 소리 하나와 짧은 소리 네 개 | 질문과 두 줄의 정확한 악보 | 종이 위 두 시간 레인과 실험 |
| 2 | spread-duration-02 | 온음표를 절반씩 나누기 | 기준 음표·분수·짧은 규칙 | 선택·분할되는 입체 음가 띠 |
| 3 | spread-duration-03 | 다른 조합으로 같은 길이 | 목표 길이와 현재 악보 | 붙여 넣는 조합 실험 |
| 4 | spread-duration-04 | 쉼표도 시간을 차지함 | 음표·쉼표 악보와 질문 | 소리 없는 구간을 유지하는 시간 레인 |
| 5 | spread-duration-05 | 템포와 비율 | 60과 120의 비교 표기 | 같은 길이의 띠와 다른 속도의 재생선 |
| 6 | spread-duration-06 | 나의 한 마디 | 만든 악보와 현재 조건 | 음표·쉼표 구성 도구와 완성 장면 |

장면 하나에 모든 설명과 문제를 억지로 넣지 않는다. 긴 교사 안내는 책 안 교사 안내 페이지에, 학생 보충 설명은 페이지의 접어 둔 종이 플랩 또는 읽기 확대에 둔다. 플랩은 본문 정답을 자동 공개하지 않으며 정답 공개·힌트 사용 기록과 구별한다.

### 5.2 처음 방문과 다시 방문

- 저장이 없으면 닫힌 표지에 “책 펼치기”가 보인다. 첫 화면에서 소리 없음.
- 유효한 저장이 있어도 표지에서 “이어서 펼치기 3”와 “처음부터 둘러보기”를 선택한다. 이어보기를 선택하면 짧은 책 열기 전이를 거쳐 저장된 펼침면으로 이동한다. 저장된 여러 장을 빠르게 모두 재생하지 않는다.
- 처음부터 둘러보기는 학습 데이터 삭제가 아니다. 삭제는 별도 확인을 거친다.
- 뒤로 돌아가기는 이전 펼침면, 표지로 돌아가기는 책 닫기의 별도 의미다. 첫 펼침면의 이전 버튼은 “표지로”라고 표시한다.
- 마지막 펼침면의 다음 책갈피는 aria-disabled이며 명령을 실행하지 않는다. 단원 마침 안내와 책 닫기·목차·다시 보기는 마지막 페이지 본문 안 별도 조작으로 제공한다.

## 6 화면과 시각 설계의 초기값

이 절의 값은 제작 시작점이다. 시제품의 가독성과 원본 비교 결과로 조정하며 변경 이유를 디자인 토큰에 남긴다.

### 6.1 화면 점유와 여백

844×390 CSS px 가로 화면에서 safe-area를 제외한 영역을 기준으로 책을 중앙에 놓는다. 안정된 펼침면의 투영 폭은 가용 폭의 약 88–94%를 목표로 한다. 페이지 턴의 높은 실루엣까지 잘리지 않도록 stage 전체는 세로 가용 영역을 사용한다. 책 종이만으로 화면 높이를 가득 채워 넘기는 페이지가 잘리게 하지 않는다.

외부 UI는 0개다. 책갈피/설정/음소거도 책에 부착되거나 책 페이지 안에 통합한다. 접근 가능한 DOM과 44×44 CSS px 목표 영역을 유지하되 시각 외부 관리 도구를 추가하지 않는다.

제공된 앞표지 원화의 제목·로고·삽화·테두리를 그대로 보존한다. 열기/intro 건너뛰기 힌트는 원화를 덮지 않는 표지 안 여백에만 최소한으로 통합한다. 대형 hero 배너·대시보드 카드·성공률 통계·설정 선택지를 첫 화면에 쌓지 않는다. 기본 3D 경로에서 페이지 조작을 하려고 문서 전체를 계속 아래로 스크롤하지 않게 한다. 작은 높이·확대·읽기 모드에서는 정상 스크롤을 허용한다.

|---|---|---|
| desk | #D9D1C4 계열 | 책보다 조용한 배경 |

| accent | #B96335 계열 | 선택·현재 박의 제한된 강조 |

색상은 원본에서 추출한 팔레트가 아니다. 한국어 폰트는 시스템 또는 권리 확인된 서체를 사용한다. 원본의 서체·손글씨를 무단으로 가져오지 않는다. 음악 기호는 일반 폰트의 임의 Unicode 기호로 대체하지 않는다. 표준 악보 렌더러와 음악 폰트 로딩 완료를 확인한다.

종이 질감은 읽기 대비를 해치지 않는 약한 변화만 준다. 3D 도식은 잉크 선화와 단순한 종이·블록 면을 조합한다. 외곽선은 원근에 따라 과하게 두꺼워지지 않게 조절한다. 전체 화면 bloom, 강한 유리 반사, 네온 효과, 회전하는 장식 악기 모델은 사용하지 않는다.

### 6.3 카메라

책은 XZ 평면에 놓고 Y를 위로 둔다. 책등은 Z축 방향이다. 진입 카메라는 v2.1 COVER-INTRO 계약을 따르고, 안착 후 학습 카메라는 책을 내려다보는 고정 사선 시점을 기본으로 하며, 초기 비교 후보는 평면 위 고도각 약 52–65도, perspective FOV 약 30–38도다. 절대 좌표는 책 크기와 전체 전이 bounds를 계산해 정한다. 이 각도가 원본의 값이라는 뜻은 아니다.

커버·책등·입체 장면의 깊이가 읽혀야 하지만 오선 판독을 원근에 의존시키지 않는다. 기본 자유 OrbitControls는 제공하지 않는다. 페이지 넘김을 보는 중 자동 카메라 회전은 금지한다. 초기 카메라는 턴 중 25/50/75%와 펼친 장면의 최대 높이를 포함한 경계를 기준으로 맞춘다. 필요한 pullback은 부드럽고 최소한으로 하고, 수치보다 가장자리 잘림 방지와 페이지의 위치 연속성을 우선한다.

악보 읽기 확대는 책 안 페이지에 귀속된 DOM/SVG 확대 읽기로 제공하며 외부 모달/패널을 열지 않는다. 책을 무한히 줌인해서 기보를 읽는 방식만 허용하지 않는다. 확대 모드를 닫으면 원래 펼침면과 선택 항목으로 돌아온다.

## 7 물리적인 책 renderer의 구현 계약

### 7.1 메시 구성

BookRoot 아래에 BackCover, Spine, FrontCoverHinge, LeftPageStack, RightPageStack, StaticSpread, TurningLeaf, ActiveSceneAnchor를 분리한다. 커버는 두께가 있는 단단한 판이다. 페이지는 곡률이 변하는 분할 메시다. 표지와 종이에 같은 회전·변형을 적용하지 않는다.

초기 월드 단위는 앞표지 front-face 폭 Cw=3.0, 높이 Ch=Cw×841.89/595.276≈4.243으로 고정한다. 페이지는 좌우 여백 mx와 상하 여백 mz를 빼 W=Cw−2mx, H=Ch−2mz로 파생한다. mx,mz는 약 0.05–0.10Cw 범위에서 조정하되 앞표지 비율은 변경하지 않는다. 커버 두께는 약 0.018–0.03W, 종이 묶음은 약 0.04–0.08W에서 비교한다. 실제 종이 한 장 두께를 화면에서 보이게 과장할 수 있지만 판자처럼 보이면 실패다. 6개 펼침면을 쓴다고 책의 두께를 6장 실제 종이와 완전히 같게 할 필요는 없으며 시각적 모델임을 내부 명세에 기록한다.

- 힌지 원점은 책등 쪽 모서리다. 커버 중앙 기준 회전은 금지한다.
- 책등과 표지가 떨어져 보이지 않아야 한다. 안쪽 힌지 접힘과 커버 바깥 면은 다른 면이다.
- 종이 묶음 옆면은 미세한 층과 약한 그림자로 표현한다. 매 장을 독립 고해상도 메시로 상시 유지하지 않는다.
- 펼침면 아래 종이·표지·책상 순서로 실제 깊이 관계가 있어야 한다.
- 커버 닫기 시 장면과 페이지가 먼저 접히고 커버가 덮는다. 입체 도식이 닫힌 책을 뚫고 나오면 실패다.

### 7.2 페이지의 앞뒷면과 순서

앞으로 넘길 때 이동하는 종이의 앞면은 현재 오른쪽 페이지 R(i), 뒷면은 다음 왼쪽 페이지 L(i+1)다. 아래 오른쪽에는 R(i+1)가 준비되어 있고, 기존 왼쪽 L(i)는 넘겨진 종이에 가려진다. 뒤로 넘길 때는 이 대응을 정확히 역전한다. 단순히 현재/다음 화면 전체를 같은 양면 texture에 붙이지 않는다.

기본 데이터 계약은 leafId, frontPageId, backPageId, sourceSpreadId, targetSpreadId다. 표지 안쪽·마지막 페이지의 예외도 명시적으로 매핑한다. 종이의 뒷면 글자가 거울처럼 뒤집히거나 90도 돌아가면 실패다. 양면 별 UV와 재질을 검증하고 종이의 얇은 옆면을 연결한다. DoubleSide만 켜고 같은 그림을 양면에 반복하는 방식은 허용하지 않는다.

### 7.3 곡면 페이지

일반 3D 모드의 TurningLeaf는 최소 폭 방향 24분할, 높이 방향 4분할 정도에서 시작해 실기기 성능에 따라 조정한다. 전체 직사각형을 rigid rotate만 하는 구현은 실루엣 테스트를 통과하지 못한다. GPU vertex deformation 또는 재사용 BufferGeometry의 CPU 변형 중 하나를 택하되, 원본이 특정 기법을 쓴다고 추정하지 않는다.

힌지에 연결된 s=0은 고정하고 s=W는 바깥 모서리다. 펼침 진행 p∈[0,1]와 드래그 방향을 입력으로 곡률을 계산한다. p=0과 p=1에서는 정확한 안정 페이지 형상과 연결되고 중간에서는 휘는 실루엣이 보인다. 구현 출발점으로 폭 방향 접선각을 적분하는 방식이나 검증된 curl shader를 사용할 수 있다. 단, 책등 고정·면 길이의 과도한 수축 방지·앞뒷면 UV·normal·bounds를 함께 해결해야 한다.

단계별로 p=0, .25, .5, .75, 1의 wireframe과 최종 렌더를 남긴다. normals가 오래되어 그림자가 반대로 생기거나 동적 bounds가 갱신되지 않아 페이지가 culling되면 실패다. 턴 중 종이 묶음 높이와 hinge 높이는 연속적으로 보간한다. 중간 프레임에서 페이지가 다른 쪽 stack 내부로 들어가거나 갑자기 높이가 뛰지 않아야 한다.

### 7.4 가림과 그림자

Opaque paper는 depth test/write를 기본으로 사용한다. 투명한 사각형을 겹쳐 가림을 흉내 내지 않는다. 넘기는 종이가 뒤의 인쇄와 도식을 실제로 가려야 한다. 장면은 넘김 전에 접혀야 하고, 아직 보이지 않는 다음 페이지의 입체 장면은 종이를 뚫고 등장하지 않는다.

초기 조명은 큰 부드러운 주광과 약한 주변광, 책·종이의 접촉 그림자를 우선한다. 책 형태를 읽는 데 필요한 그림자는 핵심 표현이다. 후처리는 장식 옵션이다. 저사양에서는 그림자 해상도·범위를 먼저 줄이고 종이 곡률·두께·앞뒷면을 먼저 버리지 않는다. 그림자 acne나 z-fighting을 무조건 depthTest=false로 덮지 않는다.

## 8 애니메이션 연출과 시간축

### 8.1 세 종류의 시계

- BookMotionClock은 커버와 종이의 진행 p를 관리한다. 사용자 드래그 중에는 손가락 위치가 시간보다 우선한다.
- SceneEntranceClock은 펼침면 안착 후 짧은 등장·퇴장을 관리한다. 음악 음가의 길이를 이 시계로 계산하지 않는다.
- MusicTransportClock은 AudioContext 기준 논리 재생 시간이다. 블록의 재생선·음표 강조·박 표시가 이 시간을 따른다.

페이지가 넘어가는 동안 음악 시계를 계속 흘려 새 페이지에 연결하지 않는다. entry 모션이 자동으로 시작되어도 소리가 자동으로 시작된다는 의미는 아니다.

### 8.2 초기 모션 토큰

| 토큰 | 초기 제안 | easing 또는 제어 | 검수 포인트 |
|---|---|---|---|
| coverOpen | 약 1000ms | easeInOutCubic 또는 단조 cubic-bezier | 단단한 힌지와 무게감, 통과·튀김 없음 |
| coverClose | 약 850ms | 출발·도착 속도 0 | 장면이 먼저 정리됨 |
| pageTurnClick | 약 1100–1150ms에서 비교 시작 | 공개 코드 기본값 참고, 단조 ease-in-out | 실제 체감 미검증, 가독성과 응답을 함께 비교 |
| pageTurnDrag | 사용자가 결정 | 위치 추적, release 후 settle | 움직임 중 시간 easing 중복 적용 금지 |
| pageSettle | 약 180–320ms | 남은 거리와 속도를 반영 | 취소 시 같은 경로로 복귀 |
| sceneEnter | 약 600ms | easeOutCubic, 짧은 순차 등장 | 종이의 anchor에서 올라옴 |

| revisitEnter | 약 180–260ms | 짧은 복귀 | 긴 도입을 매번 반복하지 않음 |
| splitMerge | 약 240ms | 단조 길이 보간 | 의미 합은 전환 전후 동일 |
| reducedMotion | 0ms 또는 ≤100ms opacity | 큰 회전·이동 없음 | 동일 state commit과 데이터 |

수치는 원본 실기 측정의 대체물이 아니다. 위 pageTurnClick은 정적 코드 기본값을 참고한 비교 출발점이고 나머지는 v2 제안이다. REF02–07을 관측한 뒤 닮음과 가독성을 비교한다. 원본의 긴 모션이 모바일 조작성에 불리하면 변경 이유를 명시하고 사용자가 선택하게 한다. 모션 값을 각 컴포넌트에 하드코딩하지 말고 하나의 BookMotionProfile로 관리한다.

### 8.3 버튼으로 다음 페이지를 넘기는 전이

1. 사용자의 next 입력을 수락하고 navigationToken을 새로 발급한다. 현재 재생을 즉시 정지하고 현재 과제 snapshot을 저장한다.
2. 현재 장면은 입력을 잃고 sceneExit를 수행한다. 오디오 정지는 모션 종료까지 기다리지 않는다.
3. 장면이 접힌 뒤 준비된 TurningLeaf를 움직인다. 움직이는 동안 이전·다음 인쇄면만 보이고 live 3D 장면은 활성화하지 않는다.
4. 종이가 목적지에 완전히 안착하면 currentSpreadId를 한 번 commit한다. 이 시점에 URL·쪽수·읽기 순서·진행 표시를 함께 바꾼다.
5. 이전 scene 리소스를 dispose 또는 비활성 캐시로 돌리고 다음 scene을 enter한다. 늦은 이전 callback은 토큰 검증 후 버린다.
6. 다음 scene entry 완료 후 상호작용을 허용한다. 음악은 사용자가 페이지의 재생 버튼을 눌러야 시작한다.

턴의 p=0.5 시점에 currentSpreadId를 먼저 바꾸면, 취소·역전 시 저장과 화면이 어긋난다. commit은 도착 확정 이후 한 번만 수행한다. 요청된 destination과 실제 currentSpread를 따로 보관한다.

### 8.4 손으로 잡아 넘기는 직접 조작

직접 드래그는 고정 시간의 click 애니메이션을 시작시키는 트리거가 아니다. 모서리를 잡은 손가락 또는 마우스의 현재 위치가 페이지 pose를 결정한다. 손을 멈추면 페이지도 그 위치에 멈추고, 반대로 움직이면 같은 종이가 연속적으로 되감긴다. 제스처 도중 시간 기반 easing을 다시 적용해 페이지가 손을 뒤늦게 따라가게 하지 않는다.

페이지 grab 위치를 leaf-local 좌표로 저장하고 pointer의 화면 이동을 고정된 camera와 page drag plane에 투영한다. 진행량 p뿐 아니라 위/아래 어느 모서리를 잡았는지와 끌어 올린 방향을 curl profile에 반영한다. 손가락은 화면 가장자리로 가더라도 capture 범위 안에서는 계속 추적한다. 화면·창을 벗어나 입력을 잃거나 capture가 해제되면 마지막 위치를 무한 외삽하지 않고 취소 정책을 따른다.

드래그용 인접 페이지 texture는 미리 준비한다. 준비되지 않은 경우 작은 모서리 pressed 피드백과 준비 안내만 보여주고 drag를 수락하지 않는다. 나중에 로딩이 끝났다는 이유로 이미 손을 뗀 제스처가 갑자기 시작되어서는 안 된다.

수락한 드래그에서는 snapshot과 audio stop을 먼저 수행한다. 버튼식 exit 시간을 전부 기다린 뒤 손을 따라가기 시작하지 않는다. 가장자리의 비어 있는 종이 영역부터 국소 curl을 반영하고, 기존 scene의 접힘 정도를 낮은 p 구간에 연동한다. 초기 제안으로 p 약 0.08–0.12 이전에 입체 장면을 종이 높이로 접고 그 이후 본격적으로 잎 전체를 넘긴다. 구체적인 curl 알고리즘은 시제품에서 충돌과 지연을 검증한 뒤 선택한다. 도식 위로 종이가 먼저 지나가는 프레임이 생기면 실패다.

released 위치와 최근 유효 샘플의 속도로 commit 또는 cancel을 한 번 결정한다. 손을 놓기 전에는 자동 완료하지 않는다. cancel은 같은 경로로 되돌아가고, 원래 장면은 snapshot에서 다시 펴지되 소리는 정지한다. commit은 남은 거리의 settle만 자동으로 이어간다. drag 도중 계속 멈춰 있는 페이지의 곡률·그림자·뒤 페이지 가림이 입력 위치와 일치해야 한다.

### 8.5 페이지 안의 음악 모션

음가 블록은 종이 도식에서 접혀 올라온 듯 등장한다. 모든 블록을 화면 밖에서 랜덤으로 날려 보내지 않는다. 1번 펼침면의 두 레인은 같은 원점과 끝점에 정렬되고, 재생선은 해당 음악 시간에 따라 지나간다. 2번 펼침면의 분할은 기존 블록 영역 안에서 경계가 생긴 뒤 두 블록으로 나뉜다. 총 폭·높이·깊이는 의미에 맞게 유지한다.

오선·음표는 표준 2D 좌표로 유지한다. 입체 악보 조형물을 학습용 정본으로 사용하지 않는다. 그림자가 박을 표시하거나, 블록 높이가 음량처럼 읽히는 표현을 피한다. 소리·높이·길이·음량이 다른 속성임을 페이지 안에 짧게 설명한다.

## 9 상태 머신과 경쟁 조건

### 9.1 하나의 큰 boolean 묶음 대신 직교 상태를 둔다

~~~text
BookState
  bootLoading -> introReady -> introMoving -> coverIdle(=closed) -> opening -> spreadIdle
  spreadIdle -> preparingTurn -> turningForward|turningBack -> settling -> spreadIdle
  turningForward|turningBack -> cancelSettling -> spreadIdle
  spreadIdle -> closing -> closed
  any operational state -> fallback2D 또는 recoverableError

SceneState
  unmounted -> loading -> entering -> ready -> playing <-> paused
  loading|entering|ready|playing|paused -> exiting -> disposed
  exiting -- drag cancel --> entering 또는 ready

TransportState
  locked -> stopped -> starting -> playing <-> paused
  playing|paused|starting -> stopped
  any -> unavailable
~~~

BookState가 spreadIdle이고 camera.settled이며 SceneState가 ready/playing/paused인 경우만 학습 입력을 허용한다. opening/closing의 cover와 camera 완료는 join barrier로 합쳐 한 번만 commit한다. 현재 scene의 소유자는 정확히 하나다. SceneState의 playing은 음악과 동기화된 학습 애니메이션을 뜻한다. 장식 entry와 실제 음악 재생을 혼동하지 않는다.

### 9.2 주요 이벤트와 처리

| 이벤트 | 허용 상태와 guard | 처리 | 도착 상태 |
|---|---|---|---|
| OPEN_BOOK | coverIdle(=closed), camera.settled, firstSpreadReady, intro 입력 토큰 소비 완료 | 커버 열기, 소리 없음 | opening 후 spreadIdle |
| NEXT/PREV | spreadIdle, 범위 내 목적지 | snapshot, stop, exit, turn | 새 spreadIdle |
| TURN_DRAG_START | page-edge owner, 인접 인쇄면 준비 | snapshot·stop, 국소 curl과 scrub exit, 최신 pointer 보유 | preparingTurn 후 turning |
| TURN_RELEASE | preparingTurn 또는 turning | 마지막 샘플과 종료결정을 저장, 임계값에 따라 commit/cancel | settling 또는 cancelSettling |
| TURN_CANCEL | preparingTurn/turning, pointercancel, lost capture, 회전 등 | gesture token 무효화, 이전 committed 페이지와 장면 복원 | 기존 spreadIdle |
| PLAY | spreadIdle, scene ready/paused, 사용자 제스처 | token 확인 후 오디오 시작 | scene playing |

### 9.3 빠른 연속 이동과 중단 정책

v2 첫 구현은 무한 queue를 만들지 않는다. 페이지 전이 중 추가 next/prev 입력은 최대 한 개의 pendingIntent만 보관하고 마지막 유효 입력으로 갱신한다. 완료된 뒤 현재 쪽을 기준으로 다시 guard를 평가해 실행한다. 10번 빠르게 눌렀다고 10장의 모션을 한참 재생하지 않는다. 반대 방향 입력은 현재 턴을 중간 순간 이동시키지 않고 현재 전이를 끝낸 뒤 한 번 반대 이동한다. 드래그 자체의 취소만 현재 턴의 역방향 settle을 사용한다.

단, CLOSE, fallback, visibility hide는 일반 pending보다 높은 우선순위다. hide에서 진행 중인 드래그는 취소하고 프로그램 전이는 마지막 committed 페이지로 복구하는 정책을 기본으로 한다. 해당 정책은 2D·reduced motion에서도 일치해야 한다. 복귀하면 정지 상태에서 다시 조작하며 자동 소리를 재생하지 않는다.

preparingTurn에서도 pointerup, pointercancel, lostpointercapture를 정상 처리한다. gestureId, 최신 좌표·시각·속도 샘플, pointerActive, releaseDecision을 보유한다. activation 전 종료는 단순 tap 또는 무효, activation 후 임계값 미달 release는 cancel, 임계값을 넘은 정상 release는 한 번의 accepted settle이다. cancel은 exit/load 완료 callback보다 우선하고, 오래된 callback이 drag를 새로 시작할 수 없다. 아주 빠른 유효 swipe의 자동 settle은 수락한 release의 결과로만 가능하며 손을 놓았는지 모르는 상태에서 뒤늦게 추적을 시작하지 않는다.

모든 비동기 로딩·resume·entry 완료·turn 완료는 bookEpoch, navigationToken, sceneInstanceId 중 필요한 ID를 검사한다. stale callback이 새 페이지를 바꾸거나 해제된 scene을 다시 mount하지 못하게 한다. abort 가능한 로더는 AbortSignal로 취소한다. 취소할 수 없는 결과도 수신 즉시 소유권을 검사해 버리거나 캐시에만 보관한다.

### 9.4 항상 참이어야 할 불변식

- 소리를 만들 수 있는 activeTransportSession은 0개 또는 1개다.
- 학습 입력을 받는 scene은 0개 또는 1개다.
- visibleSpread, currentSpread, saveSnapshot의 의미 revision이 commit 경계에서 일치한다.
- turning 중 두 개의 live scene이 동시에 재생되지 않는다.
- cancelled turn은 페이지 수·답안·완료 기록을 바꾸지 않는다.
- dispose는 여러 번 호출해도 안전하다. dispose 후 callback은 상태 변경 권한이 없다.
- 페이지 전이 progress는 저장하지 않는다. 학습 데이터와 마지막 안정 페이지를 저장한다.
- timeout은 성공의 증거가 아니다. 전이가 끝나지 않으면 안전 복구하고 오류를 기록한다.

## 10 장면 생명주기와 재방문

SceneAdapter는 load, enter, play, pause, stop, exit, captureSnapshot, restoreSnapshot, dispose의 의미를 분명하게 가진다. 실제 API 형태는 기존 저장소 구조에 맞춰도 되지만 역할을 생략하지 않는다.

load는 데이터와 필수 자산을 준비할 뿐 소리·입력을 켜지 않는다. loading이나 entering 도중에도 exit/abort/dispose할 수 있어야 하며 ready에 도달해야만 해제할 수 있는 구조는 금지한다. enter는 페이지 anchor에서 보이는 도입을 수행한다. ready가 된 뒤 입력을 켠다. exit를 시작하면 먼저 입력을 차단하고 예약 소리를 취소한다. dispose는 event listener, frame subscription, timer, audio node, 전용 GPU 자원과 참조를 정리한다. 공유 자원은 소유권 또는 참조 수를 확인한 뒤 마지막 사용자가 해제한다.

재방문 snapshot에는 사용자 음표 배열, 템포 선택, 답안, 힌트 공개 여부, 현재 유효한 평가, 관찰한 개념 단계, 콘텐츠 revision을 저장한다. hover·pointer capture·카메라 중간 좌표·AudioNode·promise·GPU object를 저장하지 않는다. 재방문 시 답안은 현재 데이터로 다시 계산하고, “예전에 성공함”과 “지금 답이 유효함”을 분리한다.

첫 방문에는 전체 entry, 재방문에는 짧은 entry를 사용한다. 진행 막대를 자동으로 이어 달리거나 재생하던 음을 자동으로 울리지 않는다. 학습자는 “다시 시연”을 눌러 전체 entry나 처음부터 듣기를 명시적으로 요청할 수 있다. entry를 건너뛰는 접근성 경로가 학습 진행을 불리하게 만들지 않는다.

## 11 터치와 페이지 안 조작의 충돌 해결

### 11.1 필수 직접 조작과 제스처 소유권

모서리 grab→연속 drag→중간 정지→역방향 당김→release 또는 cancel을 기본 3D 경로의 필수 기능으로 둔다. 페이지 flip 버튼이나 swipe 종료 후 고정 모션만 있는 구현은 이 요구를 충족하지 않는다. 클릭·키보드 버튼은 필수 대체 경로이지 직접 드래그를 대신하는 면제 조건이 아니다.

우선순위는 열린 DOM 대화상자·입력·버튼, scene의 조작 가능한 물체, 페이지 바깥 모서리 영역, 빈 책 면 순서다. 첫 pointerdown에서 owner를 정하고 같은 pointerId가 끝날 때까지 소유권을 바꾸지 않는다. 페이지 위 음가 블록을 끌다가 모서리에 도착해도 갑자기 페이지 넘김으로 바뀌지 않는다.

페이지 넘김 시작 영역은 페이지의 바깥쪽 가장자리 약 44–56 CSS px에서 시작한다. 브라우저 뒤로 가기와 충돌하는 화면 극단부 및 safe-area는 피한다. scene의 주요 조작은 이 영역과 겹치지 않게 배치한다. 캔버스 전체의 수평 스와이프를 모두 페이지 넘김으로 취급하지 않는다.

초기 drag 활성 임계값은 약 8px, 방향 우세 조건은 |dx| > 1.3|dy|를 비교 시작점으로 둔다. commit은 해당 페이지 투영 폭의 약 22% 이상 또는 안쪽 방향 속도 약 0.45px/ms 이상을 초기값으로 한다. 실제 페이지 너비와 기기에서 검증하고, 큰 스크린의 동일 px 임계값을 그대로 강제하지 않는다. 반대 방향·범위 밖·취소는 원래 페이지로 settle한다.

### 11.2 처리 세부

- pointer capture를 사용하는 동안 pointerup뿐 아니라 pointercancel, lostpointercapture, unmount, 회전도 정리한다.
- R3F의 capture는 DOM과 같은 완전 독점이 아니다. 뒤쪽 mesh로 이벤트가 전달되지 않도록 raycast 순서·stopPropagation·owner guard를 함께 사용한다. [R3F 이벤트 공식 문서](https://r3f.docs.pmnd.rs/api/events)
- 두 번째 포인터가 들어오면 앱 드래그를 취소하고 브라우저 확대를 방해하지 않는다. 전역 touch-action:none과 zoom 제한 meta는 금지한다.
- page edge는 필요한 경우 pan-y pinch-zoom을 검토하고 실제 지원 환경에서 확인한다. scene 드래그는 비드래그 대체 버튼을 항상 갖는다. [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)
- pointerup 후 synthetic click으로 페이지가 두 번 넘어가지 않게 accepted gesture ID로 소비 여부를 관리한다.
- 아무 드래그 없이 이전/다음 DOM 버튼으로 모든 페이지를 이동할 수 있다. 키보드 화살표는 입력 요소 편집 중에는 가로채지 않는다.
- 책을 넘기려는 동안 소리는 즉시 멈춘다. 페이지가 다시 돌아오는 취소 동작 후 자동 재생하지 않는다.

## 12 정확한 악보를 3D 책에 통합하는 방법

### 12.1 정본은 계속 음악 의미 데이터다

기약분수 음가, onset, note/rest, 음이름 step·alter·octave, meter, tempo.unit·bpm, notation을 보존한다. 2D 악보·3D 장면·소리·평가는 같은 validated snapshot과 revision을 사용한다. 블록의 px 폭이나 원근 투영 좌표를 다시 읽어 정답을 계산하지 않는다.

첫 단원은 4/4, C4=MIDI60, 기본 템포 4분음표=90, 비교용 60과 120이다. 분수는 온음표 길이 1을 기준으로 한다. 3/4와 6/8의 총 길이가 같아도 박 묶음은 같지 않다. 음정 이름은 도수와 반음을 함께 계산한다. C4→D♯4는 증2도, C4→E♭4는 단3도다. 이는 기존 엔진의 회귀 기준이며 첫 단원에 음정 화면을 추가하라는 뜻은 아니다.

### 12.2 정지 페이지와 움직이는 페이지를 나누어 렌더링한다

정지한 펼침면에서는 page-local DOM/SVG를 사용해 오선·기호·본문을 선명하게 표시한다. 화면상 배치는 page-local UV 사각형과 해당 카메라의 실제 투영에 연결한다. 축 정렬 bounding box에 DOM을 단순 배치하는 것만으로 종이와 일치한다고 가정하지 않는다. 네 모서리의 screen 좌표로 homography 또는 동등한 정합 변환을 계산하고, 폰트 로딩 완료·CSS pixel ratio·texture 해상도·camera 상태를 함께 관리한다. 화면에 평평한 읽기 영역으로 의도적으로 보이게 할 때는 그 영역이 돌아가는 종이에서 어느 UV 사각형으로 인쇄되는지 명시한다. 투영이 너무 기울거나 좁으면 문장을 줄이거나 읽기 확대를 제공한다. 올바른 오선 위치가 원근 때문에 바뀌어 보이도록 기호를 3D 공간에 흩어 놓지 않는다.

페이지가 움직이는 동안 DOM을 공중에 남겨 두지 않는다. 출발 전 동일 revision의 2D 렌더를 해당 종이의 texture로 준비하고, 전이 중 live DOM을 inert 및 숨김 처리한다. 종이가 안착한 뒤 texture와 DOM을 같은 위치에서 교체한다. 정지→턴 시작 및 턴 완료→정지 교체의 네 모서리와 오선 baseline 위치를 비교해 눈에 띄는 jump나 scale 변화가 없는지 검증한다. 초기 정합 오차 목표는 CSS 좌표 약 1–2px 이내로 두되 화면과 DPR을 기록하고 실제 가독성으로 최종 판단한다. 이 방식은 참고 구현 전략이지 원본의 기술을 확인했다는 뜻이 아니다.

texture는 뒤집히는 종이에 속하므로 실제 depth occlusion을 받는다. live DOM은 안정된 페이지의 안전 영역 안에서만 보이고, 3D 물체와 겹치지 않는 배치를 기본으로 한다. 꼭 겹쳐야 하면 명시적인 occlusion 검사를 도입한다. z-index를 크게 만들어 종이를 관통하는 글자를 허용하지 않는다.

### 12.3 기보 품질과 접근성

기존 VexFlow SVG 어댑터의 지원 범위와 테스트를 먼저 유지한다. font load 완료와 glyph 누락 여부를 확인하고, 악보 렌더 실패를 빈 종이로 감추지 않는다. 온·2분·4분·8분·16분음표, 대응 쉼표, 보표·마디선·빔·줄기·C4 덧줄을 음악 교육자가 확인한다. 문서의 화면 질감 때문에 보표 대비를 낮추지 않는다.

texture 안 악보는 접근성 정본이 아니다. Canvas DOM 요소 밖에 한 번만 읽히는 의미 목록과 조작 가능한 DOM 경로를 제공하되, 이는 책 바깥 시각 패널을 뜻하지 않는다. 보이는 DOM 조작은 책 페이지의 실제 투영 위치에 정합하고 스크린리더 전용 설명은 시각적으로 숨긴다. 숨겨진 이전/다음 페이지의 텍스트는 탭 순서와 스크린리더 읽기 순서에서 제외한다. focus를 매 프레임 옮기지 않으며 페이지 commit 후 새 장 제목으로 안정적으로 이동한다.

## 13 오디오와 재생 정책

### 13.1 기본 재생

페이지 진입·표지 열기·페이지 넘김 자체로 음악을 자동 재생하지 않는다. 페이지의 “들어보기” 버튼 또는 사용자가 명시한 소리 시작 제스처로 AudioContext를 생성 또는 resume한다. 실패해도 책과 시각 학습은 유지한다. 사용자 제스처를 기다리는 정책은 [Web Audio 공식 안내](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)에 근거한다.

이벤트 초 길이는 (duration / tempo.unit) × 60 / bpm이다. 화면 재생선은 같은 session의 AudioContext.currentTime 기준 논리 시간을 읽는다. requestAnimationFrame이 늦었다고 음악 예약을 다시 시작하지 않는다. 타이머는 UI 갱신에 쓰일 수 있지만 음표의 정확한 시작 시각은 오디오 시계로 예약한다. [currentTime 문서](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime)

Stop, page exit, close, 숨김, 모드 전환, 오류 시 미래 예약 source까지 실제 stop한다. 필요하면 5–15ms 정도의 짧은 gain 감쇠로 click을 줄인 후 disconnect와 참조 정리를 한다. source마다 start 호출 여부를 추적한다. stop 시각이 예약 start보다 이르면 소리가 시작되지 않는 계약을 사용한다. [AudioScheduledSourceNode stop](https://developer.mozilla.org/en-US/docs/Web/API/AudioScheduledSourceNode/stop)

자연 종료는 마지막 source.onended가 아니라 끝의 쉼표까지 포함한 논리 길이로 판단한다. 완료를 한 번 표시한 뒤 logicalOffset을 0으로 돌리고 scene ready와 transport stopped로 간다. 다시 누르면 처음부터 듣는다. 반복 재생은 사용자가 명시적으로 선택한 경우만 허용하고 페이지를 떠나면 취소한다.

### 13.2 일시정지의 v2 변경

v1은 stop 후 위치 0 정책이며 중간 재개를 지원하지 않았다. v2의 scene paused 상태를 실제 음악 일시정지에 연결하려면 **별도 구현과 테스트가 필요하다**. UI 이름만 “일시정지”로 바꾸고 처음부터 시작하는 동작은 금지한다.

v2 완성본은 logicalOffset을 저장한 pause와 해당 offset부터 resume를 제공한다. 지원 범위가 한 마디의 합성음이므로 검증된 이벤트 snapshot을 하나의 재사용 가능한 AudioBuffer로 렌더링하고, 재개할 때 새 AudioBufferSourceNode를 offset부터 시작하는 경로를 우선 검토한다. 이 선택은 기존 오디오 시간 계산을 버리는 것이 아니라 transport 어댑터를 확장하는 것이다. AudioBufferSourceNode는 한 번 시작한 노드를 다시 start할 수 없으므로 노드는 매 재생마다 만들고 buffer만 재사용한다. [AudioBufferSourceNode 문서](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode)

음표 중간 재개는 새 음악 이벤트 어택으로 집계하지 않는다. fade-in 때문에 청각적으로 다시 시작된 느낌이 들 수 있으므로 “소리 시작 횟수” 평가의 청취 완료는 중단 없는 재생으로만 인정하고 pause/resume 시도는 별도 기록한다. 시각 개념 학습 경로는 계속 완료 가능하다. 직접 oscillator 재예약 방식을 선택하면 지속음·음표 경계·쉼표 중 재개의 음향과 어택 의미를 별도로 증명해야 한다.

첫 두 펼침면 게이트에서 pause가 아직 미구현이면 재생/정지만 정직하게 제공하고 pause 항목을 미통과로 표시한다. 책 형태의 초기 승인과 v2 전체 transport 완성 판정을 섞지 않는다. 장면 전체 확장 전 재생 계약 게이트에서 pause를 완성하거나 사용자의 명시적인 범위 변경을 받는다.

### 13.3 오디오와 장면의 소유권

오디오 엔진은 책 메시의 자식 생명주기에 따라 무조건 새로 만들어지지 않는다. 앱 수준에서 단일 컨텍스트를 관리하고, 현재 펼침면의 transport session만 소리를 소유한다. async resume가 완료되기 전에 다른 페이지로 이동했다면 원래 요청은 취소된다. 같은 버튼을 여러 번 눌러도 하나의 시작 요청만 유효하다.

배경음악은 기본 없음, 페이지 넘김 효과음도 기본 없음이다. 장면이 있는 교재라는 이유로 음악 학습 중 장식음을 넣지 않는다. 합성음은 합성 학습음으로 표시하고 원본 악기 녹음이라고 주장하지 않는다. 출력 장치가 Bluetooth라면 지연 특성을 별도로 기록한다. 단위 테스트나 녹음 파형 확인은 실제 청취를 대신하지 않는다.

## 14 여섯 펼침면의 교육 장면 명세

### 14.1 첫 펼침면 긴 소리와 네 번의 시작

입장할 때 종이에 그려진 두 시간 레인이 낮게 올라온다. 위는 C4 온음표 하나, 아래는 C4 4분음표 네 개다. 두 레인은 같은 시작·끝 좌표를 사용하고 모든 블록 높이·깊이는 같다. 왼쪽에는 두 줄의 정확한 악보와 “끝나는 시각과 시작 횟수는 같을까요”를 둔다.

오른쪽 레인 옆의 페이지 인쇄형 버튼으로 위·아래를 각각 듣는다. 동시 재생은 첫 비교에서는 허용하지 않는다. 다음 페이지는 듣기·정답 완료를 강제하지 않고 이동 가능하다. 학습 완료와 책 탐색은 다른 상태다.

정답은 총 길이 같음, 음악 이벤트 어택은 1회와 4회다. 90 BPM에서 두 줄은 각각 8/3초, 아래 onset은 0, 2/3, 4/3, 2초다. “길이가 짧아져도 이 예의 음높이와 음량 설정은 바뀌지 않는다”를 확인한다. 소리를 못 듣는 경우 끝점·어택 표식·텍스트를 보고 개념 과제를 진행하며 실제 청취 기록과 구분한다.

다음 페이지를 요청하면 재생선이 멈추고 레인이 종이로 내려온 뒤 종이가 넘어간다. 재방문 시 답안과 관찰 여부는 남지만 소리는 시작되지 않는다. 이 펼침면은 시제품에서 자리표시자가 아니라 실제 악보와 합성음으로 작동해야 한다.

### 14.2 두 번째 펼침면 절반씩 나누기

종이 위 온음표 길이 띠 하나가 올라온다. 표기는 온음표 기준 1이다. 블록 선택 후 “둘로 나누기”를 누르면 선택 블록만 같은 길이 두 개로 나뉜다. 길이 합은 항상 1이다. 각 분할에서 악보도 동일 revision으로 갱신된다.

1/16보다 더 작은 분할은 막고 이유를 알려준다. 인접한 같은 길이·같은 종류·같은 음높이의 블록 둘을 합치는 역연산을 제공한다. 붙임줄 의미를 임의로 만들지 않는다. Undo/redo는 데이터와 기보·평가를 함께 돌린다. 작은 16분음표를 정확히 누르지 않아도 DOM 선택 목록과 이전/다음 선택으로 조작한다.

완료 기준은 2분·4분·8분·16분음표를 관찰하고 온음표와 같은 길이의 8분음표가 8개임을 확인하는 것이다. 모든 분할을 끝내면 16개 16분음표다. 페이지를 떠났다 돌아와도 만든 분할 상태를 유지한다. 초기 두 펼침면 검증에 이 저장·복귀 행동을 반드시 넣는다.

### 14.3 세 번째 펼침면 서로 다른 조합

목표 길이 1/2를 얇은 인쇄 가이드로 표시하고 1/4·1/8·1/16 블록을 눌러 더한다. A는 4분음표만으로 두 개, B는 8분음표만으로 네 개, C는 두 종류 이상이다. C에서 1/4+1/4는 합은 맞아도 종류 조건 미충족이고 1/4+1/8+1/8은 통과다. 하나의 예시만 정답으로 인정하지 않는다. 부족·초과는 기약분수 값으로 알려준다.

### 14.4 네 번째 펼침면 쉼표의 시간

note/rest/note/rest가 각각 1/4인 한 마디다. 쉼표의 자리는 비워 두되 시간 구간의 종이 가이드를 남긴다. 재생선은 멈추지 않는다. 90 BPM의 두 어택은 0과 4/3초다. 쉼표 구간에 내레이션·페이지 효과음이 끼어들지 않는다. note↔rest 변경은 duration을 보존한다.

### 14.5 다섯 번째 펼침면 템포와 비율

정지 상태에서 4분음표=60 또는 120을 선택한다. 한 마디는 4초 또는 2초지만 블록의 상대 길이는 변하지 않는다. 온음표 대 4분음표 비율은 4:1이다. 템포를 바꾼다고 note.duration을 다시 쓰지 않는다. 재생 중 변경은 정지 후 가능하다고 안내한다. 시간과 비율을 서로 다른 문항으로 확인한다.

### 14.6 여섯 번째 펼침면 나의 한 마디

빈 4/4 마디는 유효한 draft지만 완성 악보나 정답으로 처리하지 않는다. 음표·쉼표를 넣어 합=1, 서로 다른 음가 길이≥2, 쉼표≥1을 만족시킨다. 예시 1/2 note + 1/4 rest + 1/8 note + 1/8 note는 통과다. 4분음표와 4분쉼표만 사용하면 음가 종류는 1개다.

성공 뒤 조건을 깨뜨리면 현재 성공 표시도 해제한다. “예전에 성공한 적 있음”만 별도 관찰 기록에 남긴다. 자유 설명은 AI나 키워드로 자동 채점하지 않는다. 교사 정답 보기와 학생의 성공을 혼동하지 않는다. 마침 장면도 카드형 통계 화면 대신 완성된 악보가 책 페이지에 남는 방식으로 끝낸다.

## 15 모듈 구조와 인터페이스

기존 파일을 전부 새 이름으로 복제하지 않는다. 현재 저장소의 실제 경로를 유지하면서 필요한 book 계층을 추가하는 점진적 전환을 기본으로 한다.

현재 코드는 React와 **순수 Three.js**를 연결한다. R3F·Drei·XState·GSAP는 감사 커밋의 설치 의존성이 아니다. G1은 기존 Three.js를 출발점으로 구현하는 것을 기본으로 한다. R3F나 다른 상태·모션 라이브러리가 명확한 이점이 있다면 호환성·이관 비용·회귀 범위를 비교한 ADR 이후 도입한다. 문서에 R3F 공식 링크가 있다는 이유만으로 기존 renderer를 먼저 전면 교체하지 않는다.

BookController가 음악 정답을 계산하지 않고 LessonDomain이 표지 각도를 알아서는 안 된다. SceneHost는 validated lesson state를 받아 표현하고 선택·분할 같은 의미 명령만 반환한다. 모션 중간 좌표는 영속 데이터와 분리한다.

예시 계약은 다음과 같다. 구현 시 기존 타입과 일치하도록 구체화하고 문서의 이름을 그대로 맞추기 위해 불필요한 대규모 rename을 하지 않는다.

~~~typescript
type SpreadId = string;
type NavigationIntent = { direction: 'next' | 'prev'; source: 'button' | 'drag' | 'keyboard' };
type PageSide = { pageId: string; contentRevision: string; textureKey: string };
type TurningLeafSpec = { leafId: string; front: PageSide; back: PageSide };
type SceneSnapshot = {
  schemaVersion: number;
  sceneId: string;
  contentVersion: string;
  lessonRevision: number;
  data: unknown; // 실제 구현에서는 검증된 scene별 discriminated union
};
interface SceneLifecycle {
  enter(context: { instanceId: string; signal: AbortSignal; reducedMotion: boolean }): Promise<void>;
  captureSnapshot(): SceneSnapshot;
  exit(reason: 'navigate' | 'close' | 'fallback' | 'hidden'): Promise<void>;
  dispose(): void;
}
~~~

위 코드 조각은 완성된 라이브러리 API가 아니라 역할 경계의 예시다. unknown을 그대로 받아 저장하지 않고 런타임 schema를 통과시킨다. lifecycle promise가 영원히 대기하면 안전 복구 경로로 보내고 성공 처리하지 않는다.

## 16 저장과 이전 버전 이관

저장은 bookUiVersion, lessonSchemaVersion, contentVersion을 구별한다. 새 저장에는 마지막 안정 spreadId, scene별 검증된 draft, 답안, 힌트 상태, 현재/과거 성취, 사용자가 선택한 2D·모션·음량 설정만 둔다. 현재 전이 p나 재생 중이라는 상태는 복원하지 않는다.

v1 저장 데이터를 확인해 sceneId와 새 spreadId의 명시 매핑을 만든다. 마이그레이션 전 원본을 백업하고, 검증 성공 후 새 키에 쓰는 방식으로 원본을 보존한다. 알 수 없는 콘텐츠 버전·손상 JSON은 기존 정상 저장을 덮어쓰지 않는다. 이관이 불가능하면 이유와 내보내기 선택을 제공한다.

저장 실패는 책과 과제를 멈추는 오류가 아니다. 현재 메모리 상태를 유지하고 저장 안 됨을 알린다. 새 학습자 시작·진행 초기화·전체 로컬 데이터 삭제는 의미가 다르므로 범위를 설명한다. 전체 삭제에서는 앱이 만든 백업 키도 정리한다. 로그인·학급 서버·분석 추적·학생 음성 녹음은 새로 넣지 않는다.

## 17 모바일 접근성과 대체 모드

| 조건 | 보여줄 경험 | 유지할 것 | 금지할 것 |
|---|---|---|---|
| WebGL 가능, 모션 일반 | 닫힌 커버에서 시작하는 3D 책 | 실제 곡면 페이지·장면 lifecycle | 기본값을 패널 대시보드로 되돌림 |
| reduced motion | 정적인 책 구도와 즉시/짧은 opacity 전이 | 페이지 순서·내용·평가·사용자 선택 | 큰 커버 회전·자동 pan·무한 흔들림 |
| WebGL 불가 또는 context loss | 2D 읽기 교재 | 동일 sceneId·draft·정답·오디오 제어 | 빈 오류 화면·진행 초기화 |
| 세로 화면 | 한 페이지 읽기 또는 순차적 펼침면 내용 | 회전 없이 전체 학습 | 강제 fullscreen·orientation lock·CSS 90도 회전 |
| 200% 확대·작은 높이 | 정상 문서 흐름의 읽기/조작 | 44px 목표·텍스트 확대·악보 확대 | 본문 축소로만 맞춤 |
| 무음·청각 대체 | 시간선·어택 표식·설명 | 개념 과제 | 실제 청취 완료와 동일 기록 |

reduced motion에서 모서리 제스처를 유지하는 경우에는 잡기·release의 논리 임계값만 유지하고 큰 페이지 회전 대신 정적인 진행 표시와 즉시 페이지 교체를 사용한다. 이 대체가 일반 모션 3D 모드의 직접 drag 요구를 면제하지 않는다.

2D 대체는 실패해서 남은 구형 대시보드가 아니라 정식 ReadingView2D다. 제목·쪽수·페이지 순서·본문·정확한 악보·실험을 읽는 순서로 제공한다. 3D와 다른 위치에 있어도 같은 명령과 데이터를 사용한다. 모션 줄이기는 무조건 2D 전환과 동의어가 아니다. 정적인 3D 책을 유지할 수 있다.

가로 검수는 844×390, 667×375, 568×320과 주소창 표시 상태를 포함한다. 세로는 390×844, 360×640을 포함한다. safe-area와 동적 viewport를 반영하되 body overflow:hidden으로 확대 내용을 잘라 버리지 않는다. dvh는 브라우저 UI 변화에 맞는 단위지만 실제 키보드·주소창 조건의 시험을 대신하지 않는다. [MDN 길이 단위](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)

책 안 목차·설정 플랩은 필요한 경우 대화상자 역할, 초점 가두기, Escape 닫기, 닫은 뒤 원래 버튼으로 focus 복귀를 갖는다. 페이지 전이 중 숨겨진 DOM은 inert 처리하고 aria-busy 및 짧은 전환 알림을 사용한다. live region에 프레임마다 재생 위치를 읽히지 않는다. reduced motion 감지와 앱 내 선택을 모두 제공한다. [MDN 모션 환경 설정](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion), [W3C 상호작용 애니메이션 안내](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

| 입력 반응 | 약 100ms 내 pressed/선택 피드백 | sceneExit 완료 전에도 입력 수락 피드백 |
| DPR | 보통 1–1.5부터 비교, 상급 최대 2 후보 | 기기별 측정 후 조정 |
| renderer | 기본 한 Canvas 한 context | 페이지마다 Canvas 생성 금지 |
| 활성 자원 | 현재 장면 1개, 인접 페이지 인쇄 texture 중심 prefetch | 모든 단원 live mount 금지 |
| 초기 draw calls | 약 150 이하 출발 | 그림자 pass 포함 측정법 표시 |
| texture | 화면 크기별 1024/2048 후보, 같은 리비전 재사용 | 큰 이미지 무제한 생성 금지 |
| 오디오 시각 편차 | 유선 출력 목표 50ms 이내 | 실기기 측정, Bluetooth 별도 |

수치는 실측값이 아니다. 페이지 복잡도와 저사양 기기에 맞춰 조정하고 변경 이유를 남긴다. 성능 때문에 핵심 책 경험을 없앤 뒤 3D 게이트 통과라고 하지 않는다. 품질 축소로도 안 되면 2D 경로를 제시하고 3D 지원 범위를 제한한다.

정지한 책에서는 demand 렌더링 또는 동등한 유휴 절약을 사용한다. 움직일 때 invalidate가 필요한 프레임을 요청하고 전이 종료 후 다시 쉬게 한다. 매 프레임 React 전역 setState와 악보 전체 재생성을 하지 않는다. [R3F 성능 안내](https://r3f.docs.pmnd.rs/advanced/scaling-performance)

### 18.2 해제와 메모리 검사

공유 geometry·material·폰트·AudioBuffer는 ownership registry에서 관리한다. 장면 전용 자원은 exit/dispose 때 해제하고, 캐시는 용량·LRU 정책을 가진다. texture는 material 해제와 별도로 관리한다. ImageBitmap을 사용한다면 CPU 자원의 close도 고려한다. Three 객체를 scene에서 제거했다고 GPU 자원이 모두 해제되는 것은 아니다. [Three.js 자원 해제 안내](https://threejs.org/manual/pages/how-to-dispose-of-objects.html)

50회 왕복 전환을 5회 묶음으로 측정해 renderer.info의 geometry·texture·program 수와 앱 측 listener·timer·audio source 수를 기록한다. 브라우저 내부 캐시로 0이 아니라고 곧 누수는 아니지만, 동일 콘텐츠 왕복마다 계속 증가하는 것은 조사 대상이다. 성능 API가 없으면 측정 불가를 표시하고 다른 수단의 증거를 남긴다. 캡처 한 장으로 메모리 안정성을 주장하지 않는다.

### 18.3 context loss와 로딩 실패

webglcontextlost 발생 즉시 재생을 정지하고 마지막 committed snapshot으로 ReadingView2D를 보여준다. renderer 복구를 시도하더라도 교재를 읽지 못하게 무기한 기다리지 않는다. 자동 반복 복구 루프 대신 사용자가 “3D 다시 시도”를 선택하도록 한다. 복구 시 자원을 다시 만들고 currentSpread를 재연결하며 소리는 시작하지 않는다. [MDN context loss 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/webglcontextlost_event)

다음 페이지의 필수 texture가 로드되지 않으면 현재 페이지를 유지하고 짧은 대기·재시도·2D 선택을 제공한다. 종이를 넘긴 뒤 빈 페이지를 무한히 보여주지 않는다. 폰트 실패는 기호 누락을 드러내고 읽기 대안으로 전환한다. 네트워크 실패, WebGL 불가, 저장 실패, 오디오 실패를 모두 같은 “오류 발생” 문장으로 합치지 않는다.

기존 음악 엔진을 먼저 다 새로 작성하느라 책 검증을 뒤로 미루지 않는다. 반대로 음악 내용 없는 placeholder만으로 G1을 통과하지 않는다. 이미 있는 검증 데이터·SVG·오디오를 두 펼침면의 가장 작은 실제 경험에 연결하는 것이 이 순서의 핵심이다.

## 21 실제 화면 증거의 기준

테스트 결과에는 commit SHA, 실행 URL 또는 로컬 주소, 기기·OS·브라우저 버전, viewport·DPR, 3D/2D 모드, reduced motion 상태, 입력 순서, 날짜를 남긴다. 각 항목은 통과, 실패, 미실행, 환경 제약, 사람 승인 대기를 구별한다.

G1의 최소 증거는 다음과 같다.

1. 실제 앱의 닫힌 커버, 열림 중간, 첫 펼침면, 턴 25/50/75%, 두 번째 펼침면, 뒤로 복귀 캡처.
2. 표지 열기→첫 장면 등장→사용자 재생→모서리 잡아 넘기기→중간 정지·되돌림·release→분할→이전→다시 복귀의 끊기지 않은 화면 녹화. 클릭 자동 넘김 영상만으로 직접 조작을 통과시키지 않는다.
3. 원본 동일 행동의 관측 영상 또는 미확인 표시가 있는 비교표. 포스터 한 장은 페이지 넘김 증거가 아니다.
4. 북 상태·scene 소유자·transport session을 시간순으로 기록한 개발 로그. 민감정보는 넣지 않는다.
5. G1-A에는 실제로 작동하는 WebGL 브라우저에서 pointer 입력으로 grab·hold·reverse·release·cancel을 수행한 증거가 필요하다. 마우스, 자동 입력 주입, 실제 휴대전화 터치를 구분한다. viewport 에뮬레이션은 실제 모바일 검증이 아니다. 실제 휴대전화의 가로 터치 검수는 최종 수업 시험 준비의 필수 항목이며, 초기 G1에서 미확보면 제한을 표시한다.
6. G1-A에는 실제 Web Audio 경로의 시작·시간·정지 기술 증거가 필요하다. mock 테스트만으로 소리가 연결됐다고 하지 않는다. 출력 파형 또는 브라우저 실행 상태와 이벤트 기록으로 기술 경로를 확인하되, 실제 청취와는 구별한다. 실제 청취 기록은 최종 수업 시험 준비의 필수 항목이다. 무음 녹화나 OfflineAudioContext 분석만 있으면 청취 미검증을 유지한다.

AI 생성 이미지·디자인 목업·storybook 정지 fixture는 디자인 자료로 사용할 수 있지만 실제 앱의 동작 증거로 제출하지 않는다. 캡처 이름에 원본/시제품/2D fallback/3D 실동작을 명확히 적는다. 흰 화면을 피하려고 자동으로 2D로 바뀐 캡처를 3D 통과 증거로 쓰지 않는다.

원본 비교 체크리스트는 정적 코드 확인과 실제 관측을 별도 열로 나눈다. 책의 첫인상, 표지 힌지, 종이 곡률, 앞뒷면, 카메라 안정성, 장면의 종속 관계, 전이 시간감, 조작 응답, 재방문, 모바일 읽기성을 항목별로 평가한다. 항목마다 일치/의도적 차이/불일치/미관측과 근거를 남긴다. 정체성에 해당하는 항목의 불일치를 점수 평균으로 숨기지 않는다.

## 22 하지 않을 것과 변경 우선순위

다음은 외형을 비슷하게 보이게 하면서 실제 요구를 놓치는 대표적인 실패다.

- 현재 패널 셸 위에 책 테두리 이미지만 깔기.
- 여섯 탭 이름을 “페이지”로 바꾸고 컴포넌트만 즉시 교체하기.
- 평평한 전체 화면을 rotateY하고 실제 종이 앞뒷면·곡률 없이 page turn이라 부르기.
- 책은 캔버스에 있고 설명·악보·재생은 계속 별도 대형 카드에 두기.
- 장면 이동 후 이전 음악·timer·pointer capture를 남기기.
- 페이지 모션을 구현하지 않은 채 3D 블록이 있으므로 책 체험 완성이라고 보고하기.
- 원본 easing·스택·자산 라이선스를 보지 않고 확인했다고 쓰기.
- 자동 테스트가 통과했다는 이유로 원본 시각 비교·실기기·청취를 통과 처리하기.
- 가독성과 접근성을 포기하면서 종이 위에 모든 글자를 작은 texture로만 넣기.
- 객관적 책 시제품 게이트가 통과되지 않았는데 모든 영상·단원을 한 번에 변환하기.

충돌 시 우선순위는 사용자 명시 책 경험과 음악 정확성, 접근 가능한 동등 학습, 안정적 입력·정지·저장, 성능, 장식 순이다. 핵심 경험과 접근성을 서로 대체재로 쓰지 않고 3D 기본 경로와 동등한 읽기 경로를 함께 설계한다.

## 23 기술 근거와 착수 시 재확인

기술 자료는 2026년 10월 27일 공식 페이지를 열람했다. 이 목록은 실제 라이브러리 설치·브라우저 시험을 했다는 뜻이 아니다. 구현 착수 시 저장소 lockfile과 공식 호환 정보를 다시 비교한다.

- [React Three Fiber 소개](https://r3f.docs.pmnd.rs/getting-started/introduction): React와 renderer의 major 호환을 확인한다. 조회 시 문서는 R3F 8/React 18, R3F 9/React 19 조합을 안내하며 R3F 10은 alpha라고 명시한다. 새 버전이 있다는 이유로 alpha/WebGPU를 이번 재설계의 전제 조건으로 삼지 않는다.
- [R3F 성능](https://r3f.docs.pmnd.rs/advanced/scaling-performance)과 [이벤트](https://r3f.docs.pmnd.rs/api/events): demand 렌더링·자원 재사용·이벤트 전파를 확인한다.
- [Three.js BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html), [Material](https://threejs.org/docs/pages/Material.html), [자원 해제](https://threejs.org/manual/pages/how-to-dispose-of-objects.html): 곡면 mesh·앞뒷면·GPU 수명 구현의 근거다.
- [VexFlow 공식 문서](https://vexflow.github.io/vexflow-docs/api/5.0.0/): SVG/Canvas 기보 renderer의 API와 폰트 계약을 확인한다. 예제의 버전 문자열을 무비판적으로 복사하지 말고 현재 lockfile에 맞는 API를 사용한다.
- [Web Audio currentTime](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime), [재생 권장 사항](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices), [stop](https://developer.mozilla.org/en-US/docs/Web/API/AudioScheduledSourceNode/stop), [AudioBufferSourceNode](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode): 시간·제스처·취소·재개 설계에 사용한다.
- [Pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture), [touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action), [context loss](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/webglcontextlost_event): 터치와 복구의 기준이다.
- [모션 환경 설정](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)과 [W3C 애니메이션 접근성](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): 큰 비필수 모션의 대체 경로를 설계한다. 특정 AAA 항목을 적용했다고 서비스 전체 접근성 인증을 주장하지 않는다.

## 24 다음 실행 작업

코드를 변경하는 후속 작업이 승인되면 먼저 동반 프롬프트의 V00과 V01을 실행한다. 현재 저장소와 v1 원본을 보존하고 재사용 지도를 만든 뒤, 원본 동작 관측 가능 여부를 확인한다. 그다음 표지와 두 펼침면의 책 시제품까지만 진행한다.

현재 남은 중요한 미확정은 원본 실동작 관측과 체감 유사도, 실제 목표 휴대전화, 본문 최종 글꼴과 미제공 책등/뒷표지 표현(앞표지는 사용자 제공 원화를 채택), 음악 교육자와 청취 담당 검수다. 원본 코드 복사 여부나 새 서버 도입을 결정할 필요는 없다. 독자 구현·로컬 우선·기존 음악 모듈 재사용을 기본으로 진행한다.

**v2의 성공은 더 많은 기능이 아니라, 펼친 책 위에서 정확한 음악을 배우는 경험이 실제 화면과 조작으로 증명되는 것이다.**
